# Buurtbox-app (tech demo)

> **Status: proof-of-concept. This repository is a tech demo, not the
> production Buurtbox software.**

## What this is

Buurtbox is an open-source, offline, off-grid data hub for use during power
and internet outages, for example at municipal emergency support points
(noodsteunpunten) and community hubs (buurtcentra). It builds on the
offline-hub approach of Kiwix and Internet-in-a-Box and adds energy
management, signed offline dataset updates, and reproducible build
documentation. More at https://buurtbox.org/.

This repository contains an early tech demo of the Buurtbox: a self-hosted,
offline neighbourhood portal running on a Raspberry Pi 5. The device
broadcasts its own Wi-Fi hotspot with a captive portal that opens the
Buurtbox web app, so no internet connection is needed. It was built to
explore feasibility and requirements and to inform the design of a proper
implementation. It is not a finished or supported product.

### Included services

All services run in separate Docker containers.

| Service | Port | Description |
|---|---|---|
| Buurtbox (Rails) | 80 | Dashboard: bulletin board and navigation shell |
| Kiwix | 8080 | Offline Wikipedia and other content (ZIM files) |
| PairDrop | 3001 | Local peer-to-peer file sharing |
| Kanboard | 8090 | Shared task/kanban board (no login) |

### Prototype hardware

- Raspberry Pi 5 (8 GB)
- SanDisk 64 GB microSD card (operating system)
- SanDisk 1 TB SSD (content and data)
- Anker Prime 26,750 mAh power bank
- Junction box enclosure

**Software stack:** Ruby 3.4.2, Rails 8.1.2, Docker, Raspberry Pi OS (64-bit).

## Use of generative AI

In the interest of transparency, here is how generative AI was used in
this repository:

- **Tools:** GitHub Copilot, using Claude Sonnet 4.6.
- **What it was used for:** developing the Rails application, the Docker
  setup, and the device and system configuration for the Buurtbox.
- **Extent:** all code in this repository was generated by AI. This
  includes all 10 currently open pull requests.
- **Review and testing:** all generated code was reviewed by the author
  and tested on the hardware described above (Raspberry Pi 5, 8 GB, with
  the services running in Docker containers).

Because of this, treat the code as prototype-quality. Human review and
hardware testing reduce the risk, but this code has not had the careful
human-led design that the production software will receive.

## Future plans

The production version of Buurtbox will be developed as a separate,
from-scratch implementation, written by hand. Generative AI will not be
used to produce code, design or documentation for it. At most, AI may be
used in a read-only role, for example to flag potential bugs or security
issues in code that a human then fixes. Code from this tech demo will not
be copied into that implementation. Any future use of AI will be disclosed
in the project's documentation.

## Setup guide

### Prerequisites

- Raspberry Pi 5 (tested on 8 GB; a Pi 4 may work but is untested)
- Raspberry Pi OS (64-bit, Bookworm)
- Docker, installed via: `curl -fsSL https://get.docker.com | sh`
- ZIM files for Kiwix, downloaded from [library.kiwix.org](https://library.kiwix.org)

### 1. Deploy the app

```bash
git clone https://github.com/unless-io/Buurtbox-app ~/Buurtbox-app
cd ~/Buurtbox-app

cp .env.example .env
# Edit .env and set RAILS_MASTER_KEY (from config/master.key)
# and ZIM_PATH to the folder containing your .zim files
nano .env

docker compose up -d --build
```

### 2. Configure the Wi-Fi hotspot

Install the required packages:

```bash
sudo apt update && sudo apt install -y hostapd dnsmasq iptables-persistent
sudo systemctl unmask hostapd
```

Set a static IP for the wireless interface (`/etc/dhcpcd.conf`):

```
interface wlan0
static ip_address=192.168.4.1/24
nohook wpa_supplicant
```

Configure DHCP and DNS hijacking (`/etc/dnsmasq.conf`):

```
interface=wlan0
dhcp-range=192.168.4.2,192.168.4.254,255.255.255.0,12h
address=/#/192.168.4.1
```

Configure the access point (`/etc/hostapd/hostapd.conf`):

```
interface=wlan0
driver=nl80211
ssid=Buurtbox
hw_mode=g
channel=6
auth_algs=1
ignore_broadcast_ssid=0
```

Enable hostapd:

```bash
echo 'DAEMON_CONF="/etc/hostapd/hostapd.conf"' | sudo tee -a /etc/default/hostapd
```

Redirect HTTPS to HTTP (required for iOS/macOS captive portal detection):

```bash
sudo iptables -t nat -A PREROUTING -i wlan0 -p tcp --dport 443 -j REDIRECT --to-port 80
sudo netfilter-persistent save
```

Enable all services on boot:

```bash
sudo systemctl enable docker hostapd dnsmasq
sudo systemctl start hostapd dnsmasq
```

### 3. First-time service setup

**Kanboard:** open `http://buurtbox.local:8090` in a browser. The app
automatically logs everyone in as `buurtgenoot` (admin), so boards can be
created without accounts.

**Kiwix:** place `.zim` files in the folder set as `ZIM_PATH` in `.env`,
then restart the container:

```bash
docker compose restart kiwix
```

### Verify everything is running

```bash
docker ps                       # all containers should show "Up"
curl -I http://localhost        # Rails app: 200
curl -I http://localhost:8080   # Kiwix: 200
curl -I http://localhost:3001   # PairDrop: 200
curl -I http://localhost:8090   # Kanboard: 200 or 302
```
